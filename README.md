# LocalLLM Studio - 统一模型与推理引擎 Web 管理器

`LocalLLM Studio Web Manager` 是专为本地多模型、多推理后端设计的全功能轻量级控制台。通过图形化网页界面，轻松管理、配置并运行各类开源大语言模型（LLM）与多模态模型（VLM）。

---

## 🌟 核心特性

- **多引擎无缝兼容**：
  - **Strata**：专为 **Qwen3.8-Flash-Next (125B MoE)** 优化的异构加速引擎，支持 MTP 多 Token 投机加速、原生视觉多模态挂载及 MCP 工具调用。
  - **Llama-Prism**：专为 **三值化 (Ternary / BitNet)** 模型（如 Bonsai-2 27B）定制的极端量化高能效引擎。
  - **Llama.cpp (CUDA)**：通用高性能推理后端，完美适配 Qwen3.6-35B A3B、Qwen3.8-27B 等常规稠密与 MoE 模型。
- **智能硬件调优（已针对 Intel Core Ultra 7 270K + RTX 5070 Ti 16GB + 64GB DDR5 调优）**：
  - CPU 线程优化（计算线程 `-t 8`，批处理线程 `-tb 16`，精准适配 P 核与 E 核异构调度）。
  - 显存/内存保护：自动采用 `Q8_0` / `Q4_0` 量化 KV Cache，支持 32K ~ 64K 超长上下文防爆显存。
- **视觉多模态自动挂载**：自动扫描并关联对应的 `mmproj-*.gguf` 投影文件，赋予模型识图与图像问答能力。
- **实时日志与健康监控**：内置模拟终端实时流式推送推理日志，支持运行状态监测、一键启停与报错追踪。
- **配置持久化与一键还原**：每个模型独立保存参数配置；改乱参数随时点击「恢复推荐配置」瞬时复原。
- **生态联动**：支持一键拉起同机部署的 Comfy Desktop，协同构建文生图、图生文工作流。

## 📂 目录结构与协作关系

> 本仓库（`web_manager/`）是**自包含**的管理器核心程序：克隆到任意位置，双击其中的启动脚本即可运行。
> 模型与引擎可以放在任意目录（首次启动时在网页里指定），而本机数据（路径设置、模型调优预设）
> 都写在仓库目录内、已被 `.gitignore` 排除，不会上传。

```text
<install-root>\                   # 任意工作根目录
│
├── models\                     # GGUF 模型与多模态权重（路径可在网页中指定）
│   ├── Qwen3.8-Flash-Next-IQ3_S\
│   ├── Qwen3.6-35B-A3B-...\
│   └── ...
│
├── engines\                    # 各推理引擎程序目录（路径可在网页中指定）
│   ├── Strata\                 # Strata 引擎及 Python 虚拟环境
│   ├── llama-b10199-...\       # 通用 llama.cpp CUDA 引擎
│   └── llama-prism-...\        # 三值化专有引擎
│
└── web_manager\                # ← 本仓库（可克隆到任意位置）
    ├── manager.py              # 后端服务（基于 Python 标准库，轻量无第三方依赖）
    ├── index.html              # 现代化自适应 WebUI 界面
    ├── Launch_Web_Manager.bat  # 🚀 一键启动脚本
    ├── README.md               # 本说明文档
    ├── local_settings.json     # 本机路径设置（运行时生成，不入库）
    └── manager_config.json     # 各模型调优预设（运行时生成，不入库）
```

## 🚀 快速使用指南

### 1. 启动管理器
直接双击本仓库目录下的 **`Launch_Web_Manager.bat`**（若你把仓库放在工作根目录，也可用根目录的启动脚本）。
它会自动使用同目录的 `manager.py`，优先复用 `.venv` / `venv`，否则回退到系统 `python`。
启动后终端将显示服务信息，并自动在默认浏览器中打开控制台：
- **控制台地址**：`http://127.0.0.1:8765`

> **首次运行**：若程序尚未找到模型 / 引擎目录，网页会自动弹出 **「⚙️ 路径设置」** 对话框，
> 填入本机路径并保存即可。这些路径只写入本机的 `local_settings.json`（已被 `.gitignore` 排除），
> **绝不会上传到仓库**；之后可随时点右上角 **「⚙️ 路径设置」** 修改。

### 2. 界面操作
1. **选择模型**：在左侧列表点击想要运行的模型。
2. **确认引擎与组件**：
   - Qwen3.8-Flash-Next 自动关联 **Strata** 引擎与配套 `mmproj`；
   - Bonsai-2 自动关联 **llama-prism** 引擎；
   - 其他模型自动关联通用 **llama** 引擎。
3. **调整参数（可选）**：可在右侧面板根据需求调整上下文长度（Context）、显卡分配（NGL）、温度（Temperature）等。
4. **启动服务**：点击右上角 **「🚀 启动推理服务」**。
5. **调用与交互**：
   - 推理引擎运行在 **`http://127.0.0.1:8080`**；
   - 对外暴露标准 OpenAI / Anthropic 兼容接口：`http://127.0.0.1:8080/v1`；
   - 可在第三方客户端（如 Cherry Studio、Chatbox、OpenCode 等）中直接添加该 API 接口进行交互。

## ⚙️ 常见配置项说明

| 参数项 | 参数 Flag | 推荐设置 | 说明 |
| :--- | :--- | :--- | :--- |
| **上下文长度** | `-c` / `--max-context` | 32768 ~ 131072 | 模型的记忆容量。开得越大，KV 缓存占显存越多（见 FAQ 第 6 条的显存账） |
| **GPU 加速层数** | `-ngl` | 99 | 全满载入显卡显存计算 |
| **计算线程** | `-t` | 8 | 匹配 270K 的 8 个高频性能核心 (P-Cores) |
| **批处理线程** | `-tb` | 16 | 匹配处理 Prompt 阶段的高并发线程数 |
| **KV 缓存量化** | `--cache-type-k/v` | q8_0 / q4_0 | 压缩上下文显存占用，避免长文本时 OOM 爆显存 |
| **Flash Attention**| `--flash-attn` | 开启 (on) | 极大加速长文本计算，降低显存占用 |
| **联网搜索 (MCP)** | `--mcp` | 开启 (on) | 仅针对 Strata：自动挂载 DuckDuckGo 实时搜索与网页全文抓取 |

## 💡 常见问题与排查

1. **为什么关闭窗口后服务停止了？**
   - 控制台窗口是管理进程的守护载体，请在使用期间保持黑色命令行窗口最小化或后台运行。
2. **如何完全终止推理服务？**
   - 在网页上点击 **「⏹️ 停止服务」**，或直接在命令行窗口中按 **`Ctrl + C`**。
3. **参数调乱了怎么办？**
   - 点击网页右上角的 **「🔄 恢复推荐配置」**，再点击保存即可还原官方基准参数。
4. **第一次运行提示「设置路径」/ 找不到模型？**
   - 若本机尚未配置模型与引擎目录，页面会自动弹出 **「⚙️ 路径设置」** 对话框，填入路径保存即可；
     之后可随时点右上角 **「⚙️ 路径设置」** 更改。
   - 所有路径仅写入本机 `local_settings.json`（已被 `.gitignore` 排除），**不会上传**。
5. **「启动 Comfy Desktop」按钮不可用？**
   - 本程序不会在代码里写死 Comfy Desktop 的路径。请通过以下任一方式告知它位置：
     - 在 **「⚙️ 路径设置」** 中填写「Comfy Desktop 可执行文件」；
     - 或设置环境变量 `COMFY_DESKTOP_EXE` 指向 `Comfy Desktop.exe`；
     - 或在本目录放置 `local_settings.json`：`{ "comfy_exe": "D:/path/to/Comfy Desktop.exe" }`。
   - 三者皆无时会自动探测 `%LOCALAPPDATA%\\Programs\\ComfyUI\\` 下的常见安装位置。
6. **加大上下文后提示 `no VRAM is left for the expert cache`（显存不足崩溃）？**
   - **这不是配置没生效，而是显存不够。** Strata 启动时会先给 KV 缓存、MTP 草稿头、视觉编码器等分配显存，剩下的才给「专家缓存」（GPU 上的专家权重槽）；一旦剩余低于最低要求（约 652 MiB）就会启动失败。
   - 真实账本参考（Intel Core Ultra 7 270K + RTX 5070 Ti 16GB；显示器走核显、N 卡全空时；Qwen3.8-Flash-Next IQ3_S）：

     | 上下文 / KV | KV 缓存显存 | 留给专家缓存 |
     | :--- | :--- | :--- |
     | 64K / int8 | ~0.9 GB | **8.5 GiB** |
     | 128K / int8 | ~1.9 GB | 约 7.5 GiB |
     | 192K / int8 | ~2.8 GB | 6.6 GiB |
     | 192K / q4_0 | ~1.4 GB | 约 8.0 GiB |

   - 排查与化解，按性价比排序：
     1. **先确认 N 卡是空的**：`nvidia-smi --query-gpu=memory.used,memory.free --format=csv`（空闲应约 `0 MiB, 15995 MiB`）。**别让浏览器 / 游戏 / 其他 AI 程序占用 N 卡**——最常见的失败原因就是有残留进程占着显存。
     2. 在 Web UI 把 **「KV 缓存量化」选 `q4_0`**（KV 约减半，省显存最多、最省事）。
     3. 把**上下文调小**（如 192K → 128K）。
     4. 在 Strata 配置里加 **`--kv-resident 65536`**（KV 流式：只把一部分 KV 放显存，其余走内存；保持 int8 精度，但解码略慢、多占约 2 GB 内存）。
     5. 把**视觉编码器放到 CPU**（配置里 `vision.gpu: false`），省出 mmproj 占用的显存；代价是看图变慢。
   - 提示：在 Web UI 里对 **Strata** 模型，**「上下文长度 / KV 缓存量化 / VRAM 预留」会真正写入引擎参数**（`--max-context` / `--kv` / `--vram-reserve-mib`），无需手改 JSON。
