⚡ 1. 核心计算与显存关键参数（决定能否跑起来与速度）
上下文长度 (Context / -c)
模型能够同时记住的短期记忆容量（包含你输入的 Prompt 和模型输出的全部历史）。16384 代表 16K tokens（约 1.2 万汉字或英文单词）。
📌 调优建议：上下文开得越大，显存中保存的 KV 缓存就越大。在 16G 显存下，日常对话 16K~32K 最轻快；处理长代码或论文可开 64K。
GPU 加速层数 (-ngl / --n-gpu-layers)
指定将模型的多少层神经网络放置在 NVIDIA 显卡显存中执行计算。
📌 调优建议：填 99 表示“尽最大可能全部塞进显存”（全 GPU 加速）。如果显卡显存不足，引擎会自动将放不下的层留给系统内存与 CPU。
Flash Attention (--flash-attn on)
开启现代 GPU 硬件级别的闪电注意力计算加速算法。
📌 调优建议：强烈建议始终保持开启！在你的 RTX 5070 Ti 上，不仅能减少 30%~50% 的显存占用，还能让首字解析速度提升 1~2 倍。
内存锁定 (--mlock)
锁定物理内存。防止 Windows 操作系统在内存紧张时把大模型的部分权重偷偷置换到缓慢的硬盘虚拟内存（Pagefile）中。
📌 调优建议：建议开启。可避免长时间不用后再次提问时出现突发卡顿。
Jinja 对话模板 (--jinja)
启用 Hugging Face 标准的 Jinja2 提示词模板解析器，自动适配模型出厂自带的 System Prompt 格式与思考标签 <think>。
📌 调优建议：强烈建议开启。关闭可能导致模型分不清“用户说的话”和“自己的回答”。
🗜️ 2. KV Cache 显存量化模式（超长文本防爆显存神器）
K-Cache / V-Cache (--cache-type-k, --cache-type-v)
控制上下文键值缓存（KV Cache）在显存中的存储精度：
• q4_0：4-bit 量化。将上下文占用的显存直接砍半！在长上下文（32K/64K）下极其关键，精度损失几乎不可察觉。
• q8_0：8-bit 量化。适度节省显存，保真度高。
• f16：原始 16-bit 浮点。无任何压缩，长文本时极容易撑爆 16G 显存。
📌 调优建议：日常与长文本推荐选 q4_0；纯短文本且追求极致无损可尝试 default / f16。
🎲 3. 文本生成与采样参数（控制回答的创造力与严谨度）
温度 (Temperature / --temp)
控制输出文本的随机度与发散性：
• 0.1 ~ 0.3：极其严谨收敛，适合写代码、数学题、提取结构化 JSON。
• 0.7 ~ 0.8：标准平衡值，日常对话自然生动。
• 1.0：思维极其发散活跃（Ternary Bonsai 推荐设为 1.0）。
Top-P (核采样 / Nucleus Sampling)
只在累积概率达到 P 的最可能词语集合中进行挑选。推荐值 0.9 ~ 0.95。
Top-K & Min-P
• Top-K：每一步强制只保留概率最高的前 K 个候选词（如 40）。
• Min-P：动态相对截断阈值。自动丢弃概率小于“最佳词概率 × Min-P”的长尾离散低质词。比传统 Top-P 更不易胡言乱语。
⚙️ 4. CPU 线程与 Batch 处理
CPU 线程数 (-t) 与 Prompt 线程 (-tb)
在有 CPU 协助计算时（如 MoE 架构或部分层回退到 CPU），分配多少个计算线程。
📌 调优建议：建议设置为你 CPU 的物理大核心数（通常 5~8），并非越多越好（线程过多反而因频繁上下文切换而降速）。
Batch (-b) 与 Micro-Batch (-ub)
预填充（读取你的输入提示词）时的批处理块大小。默认 512 / 128 在显存开销与长文档读取速度之间达到了最佳平衡。
👁️ 5. 多模态视觉模块与特殊引擎扩展
视觉投影模块 (MMPROJ)
图像特征编码器。如果挂载了对应模型的 mmproj-*.gguf，模型就具备“看图”能力，支持在聊天中上传图片并进行分析。
额外参数 (Extra Args) 常见用法
• --n-cpu-moe 999：针对 MoE 混合专家模型（如 Qwen 35B A3B），开启 CPU 辅助多专家并发加速。
• --webui-config-file webui-config.json：载入特定 WebUI 界面预设。
• --host 0.0.0.0：允许局域网内其他电脑或手机访问当前模型的 API 接口。
